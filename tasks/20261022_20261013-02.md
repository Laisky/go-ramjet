## Compatibility and release impact

No database migration, stored-data rewrite, queue change, new dependency,
persistent credential, public response shape or billing change is introduced.
Receipt-capable mixed versions retain direct retrieval; provider recovery needs
both compatible services. Existing caller cancellation and worker deadlines are
unchanged. The queue still has no immediate distributed cancellation after a
worker dequeues a task.

The intentional stricter behavior is limited to the verified path: configured
provider API credentials require HTTPS, and rejected direct certificate
identities cannot be converted into provider success. Configure affected
credentialed endpoints with HTTPS before release. Anonymous HTTP and legacy
adapters retain their existing behavior.

Follow the [rollout and rollback HOWTO](../docs/manual/crawler_content_first.md#howto-rollout-and-rollback):
qualify and release the compatible worker before the capable caller. Stop new
capable submissions and drain accepted/running work before rolling back caller,
then worker. Normal release-branch pushes can deploy automatically; this task
updates only the existing PR branches.

Production retrieval has not been claimed. The independent October 20 22:16
header-timeout event still lacks a confirmed target, revision and cause.
