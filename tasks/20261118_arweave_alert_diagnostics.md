# Arweave archive alert diagnostics

## Incident and root cause

The 2026-11-18 16:31:38 UTC alert `failed to fetch and save url content` carried `{}`. A bounded, read-only container-log check for 16:31:30 through 16:31:45 found the matching failure: fetch -> submit crawler task -> admit crawler target -> non-public addresses refused. The target was an HTTP non-global IP literal with a query. The target itself is intentionally omitted. Central-log searches returned no matching rows; the incident conclusion comes from the container log, not the central index.

The refusal is expected destination-policy behavior, not evidence of a provider outage or storage failure. No target request is needed or authorized to reproduce it. The distinct notification defect is that the alert core exports fields only for the reviewed verified-crawler logger. The archive worker used the root logger, so its URL/error fields were intentionally removed by that privacy boundary. Prior crawler fixes do not cover this scope.

## Correction

Use a distinct archive logger (`log.ArchiveLogger()`, full name `log.ArchiveLoggerName`) and an intentionally bounded projection of stage, category, elapsed milliseconds and a keyed correlation reference (`target_ref`). Raw URLs, raw errors, arbitrary fields and inherited logger context remain outside outbound archive alerts; ordinary local logging retains its existing fields plus the same `target_ref`. Other logger scopes remain metadata-only, and reviewed crawler logging remains unchanged. Hook and core route through one scope selector.

Admission is owned by `library/egress`: `egress.Admit` applies the shared crawler policy and returns `*egress.AdmissionError` with a finite reason (`destination_denied`, `invalid_target`, `dns_not_found`, `dns_timeout`, `dns_failed`). Because the dependency sanitizes resolver failures into the same input error as a private destination, the resolver outcome is observed at the lookup boundary (the pattern the renderer already used) instead of parsed from text. Caller cancellation and deadlines keep their identity. The crawler's typed admission wrapper is preserved and implements the explicit `log.FailureStageError` contract; `egress.AdmissionError` implements `log.AdmissionReasonError`; both are compile-time asserted.

The archive per-item function was extracted for the actual source-path regression. Fetching, storage, the three-minute budget and existing duplicate suppression are unchanged. This does not fix or certify the existing separate Load/Store suppression race.

## Review follow-up (P1/P2)

Each finding was reproduced against `095dcaa` before the fix; none was a false positive.

- P1 `/arweave/proxy` SSRF (pre-existing): the direct fetch used a plain client. Reproduced: a loopback target served its body with 200, and `localhost` and `169.254.169.254` were dialed. Now the handler admits the target before any fetch, cache lookup or archive scheduling, and the direct fetch uses `egress.NewHTTPClient`, whose `PinnedTransport` admits every hop (redirects included), pins the connection to admitted addresses, rejects other peers and ignores environment proxies. GPTChat's verified provider transport now delegates to the same transport. Behavior change for public targets: HTTP/1.1 without keep-alive, at most 5 redirects (was 10).
- P2 expected refusals alerted at ERROR: reproduced. Expected reasons (`destination_denied`, `invalid_target`, `dns_not_found`) are now WARN in the archive worker and 400 + WARN in the handler (including malformed URLs and redirects into private networks), below the shared alert rate limiter. `dns_timeout`, `dns_failed`, fetch and storage failures remain ERROR alerts.
- P2 DNS vs private indistinguishable: reproduced (resolver timeout, deadline and SERVFAIL all became the same unexported input error as a private answer). Alerts now carry the typed reason as `category` with `stage=admission`; a resolver timeout is `dns_timeout`, not the task-budget `timeout`.
- P2 digest equals S3 object key: reproduced. `target_sha256` is replaced by `target_ref`, an HMAC-SHA256 (128-bit hex) under a per-process random key. It correlates the alert with the same process's local log line, cannot be recomputed from a URL, and is not the object key. The field was introduced by this unmerged PR, so no consumer depends on it.
- P2 logger-name compatibility: no in-repository consumer filters on logger names; OTLP exports `logger.name`, and 41 production scopes are already named below `go-ramjet`, so exact-match filters on `go-ramjet` already miss most records. External dashboards and alert rules were not available to verify; filters should match `go-ramjet.arweave.localstorage` or the `go-ramjet` prefix. A test binds `ArchiveLogger()` to the alert policy so a scope rename cannot silently revert alerts to `{}`.

Out of scope: the renderer egress fetcher keeps its own resolver capture; the proxy response body remains unbounded as before; the Load/Store duplicate race is unchanged.

## Second review follow-up (P1 proxy coordination, CodeQL)

- P1 `CacheHandler` result coordination (pre-existing): reproduced against `c1efa09` with behavioral handler tests. Workers sent successes with a non-blocking send on an unbuffered channel, so a result ready before the handler waited was dropped: an immediate live success was answered with the archive miss (first failure within 4-70 of 300 requests per run), and when both sources succeeded at once the handler answered an empty 200 without `X-Laisky-Cache-Status` (nil error from `pool.Wait`). Separately, `errChan <- pool.Wait()` blocked forever after every successful answer (one leaked goroutine per request), and the archive head start was an uncancelable `time.Sleep`. Fix: `firstAvailableContent` runs each source under its own context and reports exactly one outcome into a channel buffered for all sources; the first success wins, losers are canceled at once and any late body is closed by a bounded drain; the winner's context ends when its body is closed; client cancellation returns immediately; the head start is a timer that ends with the request. Behavior kept: live fetch first, archive after `cacheFallbackDelay` (1s), first success answers, live failure is the reported error (archive failures are now logged at DEBUG instead of discarded).
- Same path, pre-existing: an archive miss (S3 404) returned an error without closing the response body, keeping a connection and its transport goroutines busy until the 30s client timeout. Reproduced with a close-tracking dialer; the non-200 body is now closed, as `LoadContentByUrl` already did.
- CodeQL `go/request-forgery` on `LoadContentByUrl` (alert 118): it is the relocated master alert 52, whose SSRF was real on master. Sink-level regressions now call `LoadContentByUrl` directly, without the handler's admission: loopback with query, `localhost`, `169.254.169.254`, `[::1]`, a hex IPv4 literal and a private DNS answer are refused with an expected admission reason and never contacted. A mutation run with master's plain client fails all six, so the tests discriminate. CodeQL cannot see admission inside `egress.PinnedTransport`; its built-in Go sanitizers are name/regex/constant checks, and model packs are not documented for Go in default setup, so there is no honest code-level way to express this barrier. Remaining action is a reviewed false-positive dismissal.
- A repository sweep for the same coordination family (non-blocking sends of results that must not be lost, blocking sends to unbuffered channels after the receiver may have left) found no other dropped-result hedge; the ArIO gateway race is safe because its sends also select on the canceled task context.
